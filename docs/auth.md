Переработай существующую авторизацию в проекте Nuxt + NestJS с учётом следующей архитектуры.

**Хранение токенов:**
- Access JWT (10 минут) возвращается в JSON и хранится в `localStorage` на фронтенде.
- Access JWT передаётся через `Authorization: Bearer`.
- Refresh JWT (30 дней) хранится исключительно в `HttpOnly; Secure; SameSite=Lax` cookie.
- Refresh Token Rotation при каждом обновлении, с защитой от повторного использования.
- При истечении Access JWT фронтенд автоматически вызывает `/auth/refresh`, сохраняет новый Access JWT и повторяет исходный запрос один раз.
- При загрузке приложения сначала проверяется сохранённый Access JWT. Если он истёк, выполняется refresh.

**Управление сессиями:**
- PostgreSQL хранит активные сессии, устройства, IP, время создания, последнюю активность и хеши refresh-токенов.
- Redis используется для кеширования статусов сессий и немедленного отзыва доступа.
- Каждый JWT содержит `sid`.
- Пользователь может просматривать активные сессии, завершать отдельные сессии и все остальные.
- Отозванная сессия должна немедленно терять доступ, даже если Access JWT ещё действителен.

**Nuxt:**
- Централизованный API-клиент с обработкой `401`.
- Single-flight refresh внутри вкладки.
- Web Locks API для координации refresh между вкладками с корректным fallback.
- BroadcastChannel для синхронизации авторизации и logout.
- Не передавать JWT через SSR payload.
- Не обращаться к `localStorage` на сервере.
- Обеспечить корректную работу авторизации при SSR, без утечки пользовательских данных и без необоснованного отключения SSR.
- Использвоать по максимум NUXT и встроиных библиотек.

**Google OAuth:**
- `/login` → Google → NestJS callback.
- При успешном входе пользователь попадает на `/cabinet`.
- При ошибке возвращается на `/login?error=...`.
- Учесть, что Access JWT должен быть безопасно передан во фронтенд, не через URL. Предусмотреть одноразовый короткоживущий authorization handoff code для получения Access JWT через JSON после OAuth callback.

**Безопасность:**
- CSRF-защита cookie-based refresh/logout.
- Защита от XSS, open redirect, brute force.
- Безопасная атомарная ротация refresh-токенов.
- Корректная обработка параллельных refresh-запросов, сетевых ошибок и logout.
- Не хранить JWT в логах или URL.
- Не допускать бесконечных циклов refresh.
